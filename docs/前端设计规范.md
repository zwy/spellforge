# 前端设计规范 · 桌面工具 Web UI

适用项目：`91porn-download`（主参考）、`riban-ranking`（次参考）、`spellforge`。
目标：多个本地工具项目共用**一套设计语言**——同一套颜色、字体、组件和交互约定，
任何 AI Coding / 人工修改 UI 时先对齐本文档，再动手。

规范的权威来源是三个仓库里已经存在的代码：
- token / 组件库：`91porn-download/web/static/style.css`（优先），`riban-ranking/web/static/style.css`
- 交互工具：`91porn-download/web/static/ui.js`（toast / confirm / api / busy）
- 后台任务：`riban-ranking/web/static/common.js`（`watchJob` 完成边缘检测）
- SpellForge 实现：`web/static/{style.css,app.js,index.html}`（单页应用，逻辑相同）

## 0. 总则

1. **亮色纸感主题**。米白背景 + 白卡片 + 细灰边线，不做暗色主题；「工具感」来自克制的配色与边框，而不是阴影和渐变。
2. **无构建步骤**。原生 HTML/CSS/JS。样式集中在 `style.css`，公共交互集中在 `common.js` / `ui.js`，不引入 React/Vue/Tailwind。
3. **同一份 token**。所有颜色只允许来自 `:root` 变量；新项目先抄 token 段。
4. **禁止**：原生 `confirm()/alert()`、行内样式堆业务样式、暗色配色、圆角大于 14px、任意阴影（唯一允许 `--shadow`）。
5. UI 文案统一中文动词开头：「已保存」「已删除」「生成中…」「失败：原因」；按钮 2–4 字（保存 / 删除 / 取消 / 更新数据 / LLM 补全）。

## 1. 设计 Token（`:root`，逐字一致）

```css
:root {
  --bg: #f6f4ef; --card: #fff; --ink: #2a2a26; --muted: #7a7974;
  --line: #e6e3dc; --accent: #20808d; --accent-ink: #01696f;
  --warn: #b45309; --ok: #2f7d4f; --bad: #b91c1c; --violet: #6a4fd8;
  --run: #3b5bdb;
  --shadow: 0 10px 26px rgba(37,41,46,.06);
}
```

| 用途 | 值 |
|---|---|
| 页面底色 | `--bg` 米白 |
| 卡片 / 面板 | `--card` 纯白，1px `--line` 边，圆角 12px（弹窗 14px） |
| 正文 / 标题 | `--ink` 15px/1.6；标题 700、h2 20px |
| 次要文字 | `--muted` 12–13px |
| 主色（按钮 / 链接 / 选中态） | `--accent` 青绿；链接/暗字用 `--accent-ink` |
| 语义色 | 成功 `--ok` / 警告 `--warn` / 失败 `--bad` / 进行中 `--run`（蓝） / LLM `--violet` |
| 字体 | `-apple-system, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif` |
| 数字 | `font-variant-numeric: tabular-nums`（时间、比例、ID、计数必用） |
| 输入焦点 | `border-color: var(--accent); box-shadow: 0 0 0 3px rgba(32,128,141,.09)` |
| 选区 | `rgba(32,128,141,.22)`；焦点环 `outline: 2px solid var(--accent)`，offset 2px |

## 2. 布局骨架

```
.wrap（max-width 1180px，左右 padding 20px）
├─ header .page-top / .top      品牌（logo 28px 圆角8 + 名称 20px/700）+ 右侧 nav
│   nav a：muted 14px，radius 8，active = accent 色 + rgba(32,128,141,.08) 底
├─ .statusbar                   后台任务/全局状态条（无内容时隐藏）
├─ .toolbar                     搜索、筛选下拉、主操作按钮（flex wrap，gap 10）
├─ 内容：.grid（auto-fill 卡片）| .tablecard（行列表）| .panel（表单）| .detail-shell
└─ 全局浮层：.toast-root（右下）、.modal-mask
```

- 首屏直接给出工具栏和内容，不放营销式 hero。
- 移动端（≤720px）：header 换行、表单列变单列、toast 通铺底部。

## 3. 组件清单（类名约定）

|---|---|---|
| 按钮 | `.btn` / `.btn.primary` / `.btn.small` / `.btn.ghost` / `.btn.danger` / `.btn.ok` | 高 32px，radius 8；小按钮高 28px radius 7；`:disabled` opacity .5 |
| chip 徽章 | `.chip` + `.ok` `.run` `.warn` `.bad` `.violet` | 22px 胶囊，11–12px 字号；类型 chip 前缀 `type-*`（如 人物 / 产品 / 景物 / 品牌） |

## 4. 交互规范

### 4.1 异步操作
- 一切有请求的按钮必须进入 busy 态：`disabled` + `aria-busy="true"` + 文案换成「处理中… / 保存中… / 抓取中…」，结束后还原。工具函数：`UI.run(btn, fn, opts)`（`ui.js`）或在单文件应用里用 `busy(btn, text)` 返回的 reset 函数。
- 后台长任务（下载、翻译、补全）：按钮文字带进度「补全中 12/75」，页面用 `.statusbar` + `.progress` 展示；轮询结束用**完成边缘检测**（见 `common.js watchJob`），避免任务收尾写库与轮询节奏差导致状态错误。轮询刷新列表时若焦点在输入框内，推迟刷新直到焦点离开（`watchJob` 的 `guard` 参数）。

### 4.2 反馈
- 操作成功：toast（ok 绿）；失败 toast（err 红，带原因）；长任务运行中 toast（run 蓝）。
- toast 是唯一的全局反馈渠道，不用 alert；成功文案以「已」开头，失败以「…失败：原因」结尾。

### 4.3 危险操作
- 删除等不可逆操作必须走确认弹窗（91porn `UI.confirm` / SpellForge `confirmDialog`）：Esc=取消、Enter=确认、焦点落在确认按钮，破坏性确认按钮用 `.btn.danger`。
- 弹窗遮罩点击关闭；表单弹窗 Esc 同样关闭。

### 4.4 时间与数字
- 后端统一存 UTC，前端展示本地时区（`fmtTime`，兼容 ISO 与 SQLite 现行时间戳两种历史格式）；
- 所有数字用 `tabular-nums`；列表时间列宽度固定，避免跳动。

### 4.5 通用列表交互
- 卡片网格 + 分页（`.pager`）或无限滚动，空态给下一步指引（「还没有主体，从上方添加…」）。
- 搜索框带放大镜 icon（参考 CSS 的 data-uri SVG），placeholder 说明搜索范围。
- 行内编辑遵循「点编辑 → 表单出现/填充 → 保存/取消」；编辑中卡片显示「编辑中」chip。
- 详情跳转保留 ID 进 URL（`?id=` / 位置参数），刷新和分享不丢位置；长任务状态尽量进 URL。

### 4.6 键盘与无障碍
- 所有可点元素可 Tab 聚焦，`:focus-visible` 用 accent outline；dialog 用 `role="dialog" aria-modal="true"` + labelledby；toast 容器 `aria-live="polite"`；busy 时 `aria-busy`。

## 5. 图标（可选）

- 可用 vendor 的 `lucide.min.js`（见 91porn-download）；按钮内图标 15px、stroke 2、与文字间距 8px，垂直居中。
- 不强制；当前三个项目里 91porn 用图标，riban/spellforge 用文字按钮，均视为合规。图标只做辅助语义，不替代文字。

## 6. 新项目接入（约 15 分钟）

1. 拷贝 token 段（§1）到新项目 `style.css` 顶部。
2. 从 91porn-download 抄：`.page-top/.toolbar/.btn/.chip/.panel/tablecard/modal/toast/empty/notice/progress` 这些**纯展示**类（去掉业务卡片部分）。
3. 抄 `ui.js`（toast / confirm / api busy）与 `common.js`（`watchJob`、`fmtTime`），改文件头注释里的项目名即可。
4. 页面骨架按 §2；逐页对照两个参考项目的对应页面（库列表 / 详情 / 设置 / 任务页）。
5. 自检清单：
   - [ ] 颜色全部来自 token（grep `#[0-9a-f]{3,6}` 超出 token 记录的即违规）
   - [ ] 没有 `alert/confirm(`
   - [ ] 异步按钮有 busy 态 + 结果 toast
   - [ ] 危险按钮走确认弹窗，Esc/Enter 可用
   - [ ] 时间本地时区 + tabular-nums
   - [ ] 880px / 420px 两档自查截图

## 7. SpellForge 特化记录

- SpellForge 是单页应用（`index.html` + `style.css` + `app.js`），视图切换 = hash（`#browse / #subj / #gen`），`hashchange` 会同步视图。
- 场景库的风格导航用 `optgroup` 分组的 select（21 风格不适合平铺 chip）；主体类型 → chip 色映射：人物=run 蓝、产品=ok 绿、景物=warn 琥珀、品牌=violet。
- 画幅比例列表 `RATIOS` 是唯一允许的「白名单常量」来源；新增画幅先改常量。
- 桌面模式（pywebview）写请求依赖一次性 `sf_token` 注入（`app.js` 开头的 fetch 包装）——改 fetch/交互时不能绕过该包装。
- 生成结果块使用 `.prompt`（中文 13.5px / 英文 muted 13px），历史列表用 `.tablecard` 行点击回看。

## 8. 已知的跨项目「出入」（有意保留，修改前讨论）

| 出入 | 原因 |
|---|---|
| riban 顶栏用 `header.top`、91porn 用 `.page-top` | 历史命名不同；语义一致（品牌 + nav 胶囊）|
| riban 阅读器 `.reader-page` 是暗色 | 阅读体验特例，不属于通用 UI；新通用页面**不得**引用为暗色先例 |
| 91porn 表单网格 2 列、riban 弹窗单列 | 面板宽度不同；同一面板内保持一种网格 |
| 小按钮 padding 有 0 10px / 4px 10px 两版 | 高度统一 28px 即可，padding 差异不再扩散 |
| emoji（📖 / ⚙）与 lucide 混用 | 按 §5 规则：文字优先，图标可选 |

> 对新交互拿不准时：先看 91porn 同场景怎么做，其次 riban；都没有 → 按本文档推导，不要发明第二种语言。
